# Edit Prose — Native-from-scratch

원본을 *patch*하지 말 것. 한국어 native tech writer로서 이 paragraph를 **처음부터 새로 쓴다**. 원본은 *정보 보존 검증용*으로만 비교.

## 인자
- `$ARGUMENTS`: 수정할 파일 경로 + 대상 (선택: 라인·섹션·전체)

## Stage 0 — 진입 게이트 (통독·주제·골격 진단, 모든 요청의 *첫 단계* 의무)

아무리 좁아 보이는 수정 요청("이 문장만", "이 부분 톤")이라도, paragraph를 손대기 *전에* 반드시 먼저 수행한다. 이 단계를 건너뛰고 곧장 문단 패치로 들어가는 것이 *반복 실패의 진원*이다.

1. **통독** — 인용 범위가 아니라 그 문단이 속한 **섹션 전체(H2~다음 H2)**를 처음부터 읽는다.
2. **핵심 주제 1줄** — 이 섹션이 답하는 *단일 질문선(throughline)*을 한 줄로 적는다. (예: "메모리는 언젠가 풀려야 하는데 *누가* 그 시점을 정하나 → 손은 위험 → 그래서 GC")
3. **골격 진단** — 현재 척추가 그 throughline을 직선으로 받치는가? 그리고 사용자 지적이 **표면**(어휘·어미·문장)인가 **구조**(순서·중복·억지 묶음·기능 나열 척추)인가 분류한다.
4. **편집 모드 결정 (분기)**:
   - *표면만* → 아래 5-Step(문단 native rewrite)로 진행.
   - *구조* → **5-Step 금지. 즉시 `/soobak-redesign`으로 전환** (정보 원자만 남기고 척추 교체).
   - 사용자가 **"논리 전개·흐름·톤·분위기"** 같은 *창발(global) 속성*을 지적했으면 **기본값은 구조 의심** — 통독 골격 진단을 통과해 "척추는 건강함"이 확인될 때만 표면 모드 허용.
5. **하드 카운터 연동** — 같은 passage를 **2회+ 손댔으면(누적)** 그다음 지적은 무조건 구조 모드(full-block 재설계). 거듭 패치 = 척추가 틀렸다는 증거.

### 의무 출력 (Stage 0)
```
[Stage 0 진입 게이트]
1. 통독 범위: <섹션>
2. throughline(1줄): ___
3. 척추 진단: 직선 받침 ✓ / 기능 나열·순서 뒤집힘 ⚠️
4. 지적 분류: 표면 / 구조
5. 모드: edit-prose(표면) / soobak-redesign(구조)  | passage 누적 N회
```

## 5-Step Process (의무 — Stage 0에서 *표면* 판정 시에만)

매 paragraph edit 직전:

### 1. 원본 읽기 → mental dismiss
원본을 읽고 닫는다. 다음 step에서 원본 sentence 구조·어순·연결어를 carry-over하지 말 것.

### 2. 독자 의문 list (원본 보지 않고)
이 paragraph가 무엇을 답해야 하는가? 한국인 초보자가 가질 의문 list:
- "왜 이게 등장하지?" "이 단어 뜻은?" "X와 Y가 어떻게 연결?"
- 직전 paragraph로부터 무엇을 받아야 하는가?
- 다음 paragraph에 무엇을 넘겨야 하는가?

### 3. Native 새로 쓰기
한국어 native tech writer로서 의문에 답하는 paragraph 작성. 원본 sentence 구조 X. *처음부터*.

생성 시 자동 적용:
- 한국어 자연 어순 6원칙 (화제 선치·배경→주제→동사·조건→귀결·원인→결과·수식어→피수식어·시·공간 부사구 앞쪽)
- 절 결합 + ~게 됩니다 resultative (분리 + transition adverb anti-pattern)
- 인과 marker 명시 ("이는 ~ 때문" / "따라서")
- 추상 명사 → 구체 example
- ~니다 분산 + sentence 50-90자 + ≤3 sentences/paragraph

### 4. 정보 보존 검증
원본과 비교. 다음만 검증:
- [ ] 사실·수치·예시 보존?
- [ ] 메커니즘 chain 보존?
- [ ] 직전 paragraph 받는 reference 역할 보존?
- [ ] 다음 paragraph로 넘기는 setup 역할 보존?

문체·어순·연결어는 native version 우선. 원본 회귀 X.

#### 4-b. 정밀 보존 (surface 수정 — 중복 제거·어휘 치환 시 *의무*)

문체 동기의 미세 수정(반복어 dedup·동의어 치환·압축)은 명제 수준 보존을 통과해도 **단어 역할 수준**에서 정밀성을 강등시킬 수 있다. native rewrite가 아니라 원본을 *건드리는* 모든 수정에서 강제:

- **삭제 token 역할 점검**: 이 수정이 *제거한* 단어가 절의 **의미 핵**(주어 핵·목적어 핵·행위자)인가? 그렇다면 삭제하지 말고 **반대쪽 occurrence를 바꿔 써서** dedup. (`GC가 실행되는 … 스크립트 실행이 멈추면`의 `실행` 중복 → 주어 핵 `실행`을 지우지 말고 GC쪽을 `동작하는`으로 교체)
- **dedup-by-deletion 금지**: 같은 단어가 두 번 나와도 둘은 서로 다른 문법 역할일 수 있다. *어느 쪽이 의미상 필수인지* 먼저 판정한 뒤, 필수가 아닌 쪽만 재서술.
- **상태변화 술어의 주어 = 실제 locus**: `멈추다/정지하다/실행되다/돌다/걸리다` 등의 주어는 동작이 *실제로 일어나는 주체*(실행·스레드·연산·처리)여야 한다. 산출물·아티팩트(스크립트·코드·파일·프로그램)를 주어로 두지 말 것. ("스크립트가 멈춘다"✗ → "코드 실행이 멈춘다"✓)
- **ripple 재독**: 한 token을 고치면 그 문장 전체를 양옆과 함께 cold-read. 정밀성·평행·인과가 유지되는지 확인.

PreToolUse 훅은 *삭제된* 단어를 못 본다(new_string만 봄). 이 4-b는 기계화 불가 → 손 cold-read가 유일한 게이트.

### 5. 회피 어휘 grep + 영어 직역체 5 패턴 grep

회피 dictionary (`memory/edit_patterns.md` §회피 어휘 Dictionary 참조):
- 강조 부사 (매우·훨씬·자체를·쌓이는·치솟다)
- Superlative (가장·항상·모든·절대)
- 영어 idiom 직역 (매핑됩니다·가능한 한·간주될 수 있다)
- 의인화·추상 동사 (비용이 발생하다·문제가 발생하다)
- 물리 행위 동사 (깔리다·뿌려지다·박히다 등) — 추상 주어 동반 시
- 청자 호출 (~봅시다·살펴봅시다)
- 사용자 거부 dictionary (이를 위해·이때·이 과정은·여럿·이쪽·결과적으로 분리)
- 교과서 패턴 (~라는 것입니다·중요한 점은·살펴보았으니)

영어 직역체 5 패턴:
1. SVO 직역
2. Passive 정의 ("~라고 합니다")
3. 후치 정의
4. 영어 idiom (가능한 한·~려 시도)
5. 영어 명사화 (~의 실행)

검출 시 대체 후보 적용.

## Done-gate — soobak Anti-Pattern 전 영역 스윕 (의무, 인용 1문장 ≠ 작업 범위)

사용자가 한 문장을 인용하면 그것은 *같은 결함 클래스가 문서 전체에 퍼져 있다는 신고 표본*이다. 그 문장만 고치고 done 금지. 고치기 전에 결함을 아래 AP로 분류하고 **편집 영역(최소 섹션) 전체를 그 클래스로 스캔해 형제 사례를 모두 한 번에 교정**한다. 기계 게이트(훅) 0건은 *필요조건일 뿐* — 아래는 대부분 의미·수사라 손 cold-read가 유일 게이트.

- **AP1 추상 속성 선언** ("비용이 있다·대가가 따른다·~에 약하다·안전성은 ~에 달려 있다") → 선언 말고 *구체적으로 보여라*(무엇이 시간을 쓰는지·어떤 입력에서 깨지는지).
- **AP2 명사화 술어·합성·인용 라벨** ("살아 있음 표시를 남긴다·「표시」와 「회수」를 나누어 처리·~하는 데에는") → 동사로 풀어라.
- **AP3 교과서투** ("핵심은 ~ 점입니다·정의 나열") → 대조·동기 구문.
- **AP4 동기 없는 새 주제 투척** ("다른 방식으로는 ~이 있습니다", 약점·용어 bridge 없이) → 왜 지금 보는지 한 절 먼저.
- **AP5 행위자 부재·오류** (산출물이 멈춤 주어·해제 행위자 없음) → 실제 행위자 명시, 상태변화 술어 주어=locus.
- **AP6 어휘 register·정밀** (메모리를 푼다→해제·모습→경우·군더더기 부사) → 도메인 정확어·정확 명사·부사 제거.
- **AP7 미설명 용어 cold 등장** → 조건·맥락 먼저 → 용어 명명 → 즉시 설명.
- **AP11 인접 문장 관계 미표지(이음새)** — 주장 문장 뒤 *근거* 문장을 인과 표지 없이 병렬("~없습니다. ~있습니다.")로 두지 말 것 → `~때문입니다 / ~므로 / 이는 ~ 때문`으로 명시. **편집 영역의 인접 문장 쌍마다 관계(확장·인과·대조·예시·결론)를 식별하고 연결어가 그 관계를 표시하는지 확인.** 각 문장이 고립적으로 깨끗해도 문장 *사이* 관계가 안 보이면 실패(문장 단위 cold-read의 맹점).
- **AP12 인트로↔본문 preview→detail 에코 (헤딩을 넘는 이웃 — 내 인트로 편집이 심는 회귀)** — *섹션 도입부(H2 인트로)를 편집했다면*, 확정 전에 **바로 다음 하위섹션 첫 문단까지 함께 읽어** 같은 메커니즘을 *같은 층위*로 반복하지 않는지 점검. 인트로는 개념을 *예고*만, 상세·명명·정밀화는 본문이 *전진*시켜 받는다. 판정: 표면 문구가 겹쳐도 본문이 도입의 예고를 넘어 *전진*하면 허용, 전진 없이 되풀이면 에코=실패. 이 구분은 의미적이라 grep·denylist·단일 new_string 훅이 못 잡는다 — *다음 하위섹션 opener 동반독*이 유일 게이트. (사례: H2 인트로에 "컴포넌트 목록을 차례로 확인하는 검색"을 넣어 다음 `### 선형 검색` opener와 겹침 → 본문을 "앞에서부터 하나씩 … 처음으로 맞는 것을 반환"으로 전진시켜 해소.)
- **AP13 시스템 경계 무명시 (2026-07-03 이상본 #3)** — 두 시스템의 판정이 갈리는 현상(C# 컴파일러=합법 / Unity 직렬화=미지원)을 무주체 은유("컴파일 단계에서 걸러지지 않는다")로 뭉개지 말 것 → **두 시스템을 각 문장의 주체로 명명**하고 결과 절마다 원인을 재진술("정상적인 C# 필드**이므로** 컴파일됩니다 / Unity 기본 직렬화의 지원 대상이 아니**므로** 표시되지 않고"). `~이므로` 반복은 허용 — 간결 규칙(filler 삭제)을 load-bearing 인과 고리에 적용하지 말 것. "오류가 발생하다"는 표준 연어(회피 사전 과교정 금지).
- **AP14 API-first 도구 소개 (위치 불문 — 2026-07-03 이상본 #3)** — 새 API/도구를 소개하는 문장은 *어느 문단에 있든* 필요·전략 평서가 먼저다("Unity가 지원하는 형태로 바꿔 두어야 합니다") → "**이때 사용하는 인터페이스가** `X`입니다"로 도구 명명. "`X` 인터페이스로 우회할 수 있습니다" 같은 API-first 개시 금지. 이 규칙을 '도입 문단 전용'으로 좁게 스코핑해 비도입 문단에서 미적용한 것이 재발 근본 — 위치 조건이 아니라 *대상 유형 조건*(API 소개 문장이면)으로 발화시킬 것. 부속: 행위자+기지 비유 접지("Unity는 ~를 일반 필드처럼 저장")·구성요소 정밀 명사(키와 값·`List<TKey>`)·메커니즘 핵심 부사("순서대로") 보존·시간 표지는 독자 행위 층위("저장 직전"·"다시 불러온 뒤").

## 의무 출력 형식

매 Edit 직전 출력:

```
[Native-from-scratch]
1. 독자 의문: ___
2. Native paragraph: ___
3. 정보 보존: ✓ / ⚠️ N건
4. 회피 어휘 grep: 0건 ✓
5. 영어 직역체 grep: 0건 ✓
6. AP1~7 전 영역 스윕: 클래스별 해당 0건 ✓ (인용 문장만 ≠ done)
```

## 수정 완료 후 회고 (매번, 솔직하게 — 항상)

수정을 마치면 반드시 다음을 자문해 보고한다. 자기에게 유리하게 포장하지 말 것:
- ① 글 전체를 통독했는가?
- ② 논리 전개 순서·구조의 적절성을 고려했는가? (표면 다듬기에 갇혀 골격을 안 본 것은 아닌가)
- ③ 표면 패치가 아니라 필요한 만큼 전면 재수정을 한 것이 맞는가?

하나라도 "아니오"면 그 자리에서 다시 한다. **'최소 수정'·'멀쩡한 문장 보존'은 사용자 규칙이 아니므로 범위를 좁히는 근거로 쓰지 않는다** — 회귀는 재작성을 피해서가 아니라 재작성 결과를 기계 검사해서 막는다.

## 제약

- 정보 누락 0건 (사실·수치·예시·메커니즘·전환 역할)
- 원본 sentence carry-over 0건 (구조 X)
- 회피 어휘 0건
- 영어 직역체 5 패턴 0건
